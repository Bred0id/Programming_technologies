# Описание задания

## Bash. Фильтрация логов

## Краткое описание задания

Целью этого задания является создание скрипта, который находит логи (все файлы с расширением `.log`), валидирует и печатает их в порядке убывания по параметру `id` (описано в следующих пунктах)

---

## Процедура сдачи задания

1. Создайте ветку `bash/logs` в репозитории, в котором реализовывали предыдущие задания.  
2. Создайте папку `bash/logs` в созданной ветке.  
3. Создайте исполняемый скрипт с названием `parse-logs.sh`  
4. После завершения задания отправьте SSH-ссылку на репозиторий в систему.  
5. Создайте Merge Request из ветки `bash/logs` в ветку `main`.  
   **Важно.** Если Merge Request не будет создан или в Merge Request будет конфликт, то задание автоматически отправляется на доработку.  
6. Если ваша посылка получила статус `ON_REVIEW`, то ожидайте ответа от Вашего ассистента.  

---

## Входные аргументы

```
parse-logs.sh [OPTION]... DIR
DIR - logs directory
```

### OPTIONS:

```
-l, --lines NUMBER        Limit, default is '10'

-o, --order [up|down]     Returns top `NUMBER` logs if is 'up', otherwise last `NUMBERS`.
                         Default is 'up'
```

---

## Позиционные

1. Директория, где располагаются логи

## Именованные

- `-o` или `--order`: up OR down (по умолчанию up)  
- `-l` или `--lines`: limit (по умолчанию 10)  

---

## Требования

Вам необходимо собрать все данные из файлов расширением `.log` внутри найденной директории.

Корректный формат логов задан следующей регуляркой:

```
[_<descriptor>_]dd:mm:yyyy_<id>_<message>
```

где:

- `_` — пробел  
- `\n`, `\r` и др. — пробельные символы  
- `dd:mm:yyyy` — дата (день-месяц-год)  
- `<descriptor>` — уровень логирования (одно из `INFO`, `DEBUG`, `WARNING`, `ERROR`)  
- `<id>` — неотрицательное целое число (идентификатор лога)  
- `<message>` — произвольное сообщение из латинских символов или символа подчеркивания (может быть пустым)  

Вам необходимо отфильтровать все собранные логи и отсортировать их в убывающем порядке по параметру `id`.

---

## Вывод

- Первые `lines` логов в случае выбранной опции `up`  
- Последние `lines` логов в случае выбранной опции `down`  
- Если количество корректных логов меньше, чем было указано, то выведите в стандартный поток вывода все корректные логи  

---

## Советы и подсказки

Вы не обязаны следовать всем советам. Можно реализовать своё собственное решение.

- Используйте механизм регулярных выражений (`regex`) для фильтрации логов  
- Вам могут понадобиться команды: `sort`, `head`, `tail`  
- Команда `cat` предназначена не только для вывода информации на экран, но и для конкатенации файлов  
- Возможно, понадобится создавать временные файлы для хранения промежуточных данных
